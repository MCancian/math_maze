# Design

What the game must do, in plain words. The code is how it does it; these files are what.
Read them as a parent or a teacher would: no code names, no file paths, no jargon.

Each feature file has three parts. **Requirements** is what ships today, in the present
tense. **Decisions** is why it is that way. **Planned** names the open milestones that
touch the area, one line each, without stating what they will require, so a design file
never contradicts an open issue.

Plan text written before 2026-09-07 lives at the git tag `plans-v1`.
